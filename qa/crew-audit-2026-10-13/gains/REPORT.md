# Gains and net worth audit

Current working tree, 13 October 2026. Application files unchanged. All data fictional. Browser: isolated Microsoft Edge profiles, local server at localhost:8000.

## Findings

1. **P1 — account-to-account transfers need a source and destination.** A EUR 500 transfer from Alpha Broker to Beta Broker leaves both portfolios unchanged economically. With opening balances 1,000 each and closing balances 500/1,500, one Investments row `Transfer from Alpha Broker to Beta Broker`, amount -500, produces gains -500/+500. The row ties on account names. Its total is zero; Review remains available and the Accounts warning identifies the unlinked transaction. Following the actual Link them to accounts UI and selecting Beta changes gains to -500/0, total Markets -500, and unmatched change +500. The suggested correction cannot encode both sides. Expected: gains zero for both accounts. Code: index.html:4035 (single account selection), :4036 (one account receives the flow), :4167 (one account selector). Recommendation: explicit transfer source/destination, with one operation feeding both accounts; retain single bank-side transfers as a separate case. Until supported, explain how to represent both legs without creating duplicate income/spending. Evidence: broker-transfer.json/png, broker-transfer-linked.png, results.json.

2. **P2 — retained income is a supported accounting limitation with weak transaction-entry guidance.** Alpha Broker rises 1,000→1,100 solely from a retained dividend of 100. Recording the dividend under Income/Dividends gives Gains 200 and unmatched change -100. Expected economic gain: 100. The calculation correctly assumes every linked return row was paid outside the portfolio; it cannot express retained versus paid-out income. The hidden Gains help already warns against recording retained dividends, so this is not an undisclosed formula regression. Code: index.html:2201 (warning), :4045 (balance growth plus every linked return). Recommendation: ask where the return went at entry/review, exclude retained income from payout additions, or give an inline warning when a broker income row is being imported or added. Evidence: retained-dividend.json/png. Net worth total itself remains correct at 2,100.

3. **P2 — one missing contribution override disables all reviewed monthly overrides for a multi-month comparison.** July→September Alpha rises 1,000→1,500. Reviewed August contribution is 300; September has a linked deposit of 200. Expected gain zero if the reviewed month and the linked month are combined. Actual gain is 300, because September lacks a contribution override and the whole comparison falls back to the linked 200. This is the current documented all-or-nothing policy, not a hidden policy violation; it is a damaging design choice when snapshots have gaps. Code: index.html:4041-4042. Recommendation: per-month fallback (reviewed value if present, else linked flows), or show which reviewed contributions were ignored and require explicit coverage confirmation. Evidence: partial-contributions.json/png. The current What changed view hides detailed decomposition because August has no tracker rows; Accounts still displays the inflated 300 gain.

4. **P2 — Net worth CSV metadata columns default to new assets.** Real upload `balances-with-contributions.csv` contains Month, Main Bank, Alpha Broker, Alpha Broker net contributions, New Pension. Cash 1,000 + broker 1,250 + pension 500 should total 2,750; the contribution 200 is cashflow metadata. The review defaults it to a new account; accepting imports four accounts and total 2,950, without saving any contribution override. Instructions explicitly require one column per account (index.html:2224, :2231), so balance-plus-contribution CSV is outside the advertised schema. The issue is permissive interpretation of a recognizable metadata column, not a failure of documented contribution CSV support. Code: index.html:4668 (every numeric headed column becomes account), :4752 (new columns default to importing accounts). Recommendation: recognize contribution/return/fee metadata names and default to skip with a clear explanation; alternatively support typed balance/contribution column pairs. Evidence: nw-csv-results.json, csv-contributions-as-account.png. The user can prevent this by choosing Don't import for the extra column.

Contribution metadata hazard reproduced through actual upload/review/apply.

## Limits

Custom scenarios seed account/balance JSON through the test hook, then use rendered screens, actual Add transaction for the retained dividend and UI linking for the transfer; the custom CSV test uses actual file parsing. Existing gains checks exercise actual transaction and pasted-import entry; existing review tests inject synthetic AI results, bypassing a live model. No live financial accounts or API keys used. No application edits made. Initial sandbox Edge launches failed; isolated launches passed after approved escalation. Screenshot evidence complements programmatic assertions; it is not a full visual design audit.
